# Jetson 视频工作台：独立运行包

> 本文介绍完整离线包。GitHub 仓库未包含随包浏览器、离线依赖、引擎与双击程序；从 GitHub 克隆后，请先阅读 [源码版部署指南](docs/GitHub源码部署指南.md)。下文的双击、离线启动和附件说明需要完整运行包中的相应文件。

完整图文报告优先阅读 [部署与提速技术报告 PDF](reports/技术报告/Jetson视频工作台_部署与提速技术报告.pdf)，同目录提供 HTML、Markdown、可编辑 Word、插图和数据来源校验。报告涵盖 TensorRT、并行/NVENC、原生后处理、CUDA Graph、网页调度、精度、INT8/DLA 与 BoT-SORT/ReID 对照。

**512 精度更新：** 刷新网页后，“极速512（去重优化）”仍为每帧一次检测，NMS改为0.55；新增“人群细节512（分区增强）”，每帧全图＋四分区共5次推理，适合MOT20拥挤人群，速度明显降低。完整对照和结果截图见 [512密集人群优化报告](reports/512密集人群优化/512密集人群精度优化报告.pdf)。同时修复826像素等宽度的NVENC输入行对齐，保存原尺寸。

把整个文件夹或 ZIP 发给接收方，保留内部目录结构。解压后，**双击根目录的 `双击启动网页` 文件**即可。这是随包编译的 Jetson ARM64 启动程序，移动整个文件夹后仍能定位网页、模型和离线依赖，不需要输入终端命令。本机桌面另有同名“Jetson 视频工作台”快捷方式。

启动时显示进度窗口，首次自动安装随包依赖、检查 CUDA/TensorRT 和视频编码器，然后打开网页。服务在后台运行，关闭进度窗口或浏览器不影响服务；再次双击直接打开已有网页，不会重复启动。端口默认 8765，若被其他程序占用会自动寻找空闲端口。重启电脑后再次双击即可启动。

**解压请用系统“归档管理器”或 `unzip`，保留 Linux 可执行权限。** 若接收方文件管理器提示没有执行权限，可在 `双击启动网页` 的“属性 → 权限”中勾选“允许作为程序执行”，之后直接双击。启动失败时窗口显示错误，点击“查看日志”；完整日志保存在 `.state/service.log`。

仅供开发调试的终端入口仍保留：

```bash
bash 启动网页.sh
```

**运行设备：Jetson Orin，JetPack 6.1/6.2、TensorRT 10.x、Ubuntu 22.04、aarch64、Python 3.10。** 本机为 Orin NX 16GB、CUDA 12.6、TensorRT 10.7；不是 Windows 浏览器直接双击 HTML 的安装包。系统需有 JetPack 自带的 TensorRT/CUDA/OpenCV，以及 python3-venv、python3-tk、ffmpeg（libx264）。若是干净系统缺少这些系统组件，先执行 `sudo apt install python3-venv python3-tk ffmpeg python3-opencv`，并确认 JetPack TensorRT Python 绑定已安装。Python 依赖、界面中文字体和 ARM64 浏览器已随包提供，正常启动无需再下载。引擎版本不匹配时会用包内 ONNX 重建正式 FP16 引擎，可能需要数分钟，进度窗口和日志会显示准备情况；INT8 实测退化，不在普通启动时重建，手动实验可能需要数十分钟。

开始检测：

1. 选择模式：`UAV/MultiUAV-003.mp4` 用“无人机”；MOT17、MOT20、VisDrone 地面人车视频用“COCO 80”。
2. 点击文件夹按钮，从 `videos/` 选素材，也可以选自己的视频；输出默认是包内 `outputs/`。
3. COCO 默认为“1280 小目标优先”；“640 均衡”保留原相机运动补偿。固定横向画面可选“640×384 固定机位”（网页实测约 104 FPS）或“512×320 极速”（约 117 FPS，小目标更容易漏检）；移动镜头选“640×384 移动镜头”（约 90 FPS）。数字来自 MOT20-01，每帧检测并保存，其他素材会不同。INT8 实测更慢且精度下降，只留作实验。
4. 点击“启动追踪”。结束后回放结果，下方显示 mAP。自己的视频没有人工 GT 时仍能检测，但 mAP 显示无法评估。

2026-10-15 起默认使用并行流水线：TensorRT 检测、相机运动特征提取、BoT-SORT 关联、画框与视频输出可以重叠执行。JetPack 有可用 NVIDIA 编码器时，直接硬件编码 H.264 MP4；其他兼容环境自动使用 FFmpeg 软件编码，不再先存 MJPEG 再转码。原始输入帧和输出尺寸都保留，未跳帧检测。mAP 匹配循环也提供原生加速，规则与 pycocotools 一致；原生库不可用时自动回退参考实现。实测对照和取舍见 `reports/性能优化报告_20261015.md`。

原始视频见 `videos/`，检测结果见 `outputs/`，每次执行独立子目录。输入不能拿画过框的视频充当原始评测视频。mAP 需要同名 `.gt.json`，格式见 `docs/mAP标注格式.md`。

代码入口见 `docs/代码导航.md`；精度问题与 INT8 对照见 `reports/精度排查与交付报告.pdf`（也提供 Markdown/HTML）。旧工程的实验、训练源码和历史输出不在运行链路内。当前运行包启用 TensorRT 和 BoT-SORT，ReID 关闭，不能把检测 AP 当成跟踪 IDF1。`app/config.json` 中 `hardware_encoder` 和 `async_camera_motion` 默认开启；1280 与标准 640 的 CUDA Graph 默认关闭；矩形速度方案实测有效，默认开启。启动无需管理员密码。

维护人员可在确认没有检测任务后，用系统监视器结束本包 `app/server.py` 进程以停止后台服务。调试时可用 `STUDIO_PORT=8766 bash 启动网页.sh` 指定端口。

本轮百帧优化见 `reports/百帧优化与DLA验证报告_20261015.pdf`（另附 Markdown/HTML 和原始指标）。硬件查询到两个 DLA 核心，实际构建和测量的是 core 0，尚未测双核并行；当前 YOLOv12 的 DLA/GPU 混合方案更慢，因此不默认启用。需要最大吞吐时，可先双击 `启用高性能模式`，由系统授权窗口输入管理员密码；本次开机有效，重启后恢复默认，不保存密码。速度方案预览为 640 宽、4 次/秒，输出视频仍保留所有帧和原尺寸。

完整实验日志的压缩归档保留在本机 `reports/benchmarks/`；可转发 ZIP 提供报告、指标摘要、验证代码和运行所需的全部文件。

启动遇到GPU内存不足时会停止并提示释放内存，不把此类资源不足误判为引擎需要重建；已验证的模型文件会保留。
