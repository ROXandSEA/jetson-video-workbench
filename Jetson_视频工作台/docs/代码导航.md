# 代码从哪里看

日常使用双击根目录 `双击启动网页`。配置修改从 `app/config.json` 开始，全部包内路径都是相对路径。

| 目录或文件 | 做什么 |
| --- | --- |
| 双击启动网页 | ARM64 可执行入口；以自身路径找到包内启动器，无须终端 |
| tools/desktop_entry.c | 上述入口的完整 C 源码；文件内有本机编译命令 |
| tools/desktop_launcher.py | 图形进度、重复点击锁、自动端口、后台服务与浏览器打开、失败日志 |
| 启用高性能模式、tools/performance_mode.py | 独立可选 GUI 入口，通过系统授权运行 jetson_clocks；不保存密码 |
| 启动网页.sh | 创建离线环境、校验模型/环境并启动服务；保留供开发调试 |
| app/web/ | 网页布局、样式、播放器、任务状态、运行方案与 mAP 显示 |
| app/server.py | 本机 HTTP 接口、文件选择、视频 Range 播放；不在启动时加载 GPU 模型 |
| app/jobs.py | 单任务管理、取消、状态快照和结果目录 |
| app/jetson_runtime.py | 有界并行流水线调度、指标、取消、资源释放与 mAP 入口 |
| app/pipeline_workers.py | 提前一帧解码/预处理、异步 TensorRT、相机特征、画框/日志/预览、NVENC 直出 MP4 和 FFmpeg 回退 |
| app/pipeline.py | 路径、标签读取与运行入口转发；编码在 pipeline_workers.py |
| app/evaluation.py | COCOeval 与 GT 视频哈希、帧数、尺寸、类别校验 |
| app/fast_coco.py、runtime/native/coco_match.c / .so | COCO 单图适配与 double 精度原生匹配循环；不能加载原生库时回退 pycocotools |
| runtime/backend.py | TensorRT 10 原生执行、CUDA 缓冲、letterbox、NumPy/OpenCV NMS |
| runtime/frame_ops.py、runtime/native/frame_ops.c、nms_bridge.cpp、yolo_reduce.cu | RGB 排布、类别筛选、浮点值不变的 JSON、逐类 NMS、GPU 输出压缩；原生库缺失时回退参考实现 |
| runtime/spatial_detail.py | 512分区增强：四个重叠局部视图、边缘截断过滤、原图坐标恢复、全局按类合并与取消；每源帧共5次推理 |
| vendor/botsort/tracker/ | 已适配的 BoT-SORT；严格按类别关联，避免 ID 跨类别；稀疏光流相机运动补偿 |
| models/ | 无人机/COCO ONNX、引擎、标签、哈希与构建元数据；INT8 另附层信息和校准缓存 |
| tools/build_engine.py | 仅依赖 TensorRT 的 FP16/INT8 构建；INT8 要真实校准视频 |
| tools/check_environment.py | 依赖/编码器/引擎验证，版本不匹配时本机重建 FP16 |
| tools/benchmark_accuracy.py | 两段固定 60 帧的 AP 与隔离推理延迟复测 |
| tools/benchmark_pipeline.py | 用完整原视频对照生产流水线的真实总耗时、输出帧数和 AP；可指定旧代码目录及 CUDA Graph 开关 |
| tools/benchmark_ceiling.py、tests/browser_ceiling.cjs | 顺序测试百帧方案、真实网页预览及回放、取消和错误标注；报告完整任务与处理 FPS |
| tools/benchmark_small_input.py、benchmark_small_web.py、tests/browser_small_input.cjs | 512精度方案的冻结样本探索、完整视频对照和真实浏览器回放/取消验证 |
| tools/export_shape.py、tools/compare_tracking.py | 开发阶段从原训练项目导出静态矩形模型；用官方 MOT20-01 ID 标注做辅助身份质量对照 |
| tools/cleanup_intermediates.py | 显式执行时先归档实验记录，再删除指定可再生成的中间文件；检测活动进程 |
| tools/organize_workspace.py | 本机一次性整理工作区；默认仅说明计划，执行时逐项验证、归档和记录删除/去重 |
| tools/make_technical_report.py | 从实测 JSON 生成综合技术报告、图表、PDF/HTML/Markdown/Word，复用历史摘要，不运行新推理 |
| tools/package_delivery.py、verify_delivery.py | 生成转发ZIP与SHA清单；打包完成后，在中文带空格新路径全新解压、离线启动并验证429帧GPU任务及H264完整解码 |
| environment/ | 锁定版本及 aarch64 Python 3.10 离线 wheel |
| videos/ | 原始输入视频与同名 GT；和输出分开 |
| outputs/ | 每次任务独立子目录：MP4、CSV、两份检测日志、耗时、mAP 与错误日志 |
| reports/ | 本次排查图文报告与实际实验记录 |
| tests/ | mAP 正确性、运行方案与真实浏览器验证脚本 |

运行时不依赖旧工程、PyTorch、Ultralytics、FastReID 或旧虚拟环境。YOLO 模型以 ONNX 与 TensorRT 格式提供；模型结构已包含在 ONNX 图中。当前 ReID 关闭，BoT-SORT 使用运动、位置和相机运动补偿，不能把检测 mAP 的变化称为 ReID 的收益。

输入模型是 [1,3,H,W] RGB /255，包含方形及静态矩形。引擎原始输出 [1,84,N]（COCO）或 [1,5,N]（UAV）：中心 xywh 加类别概率，没有单独 objectness。不能额外乘一个并不存在的 objectness。COCO 可在 GPU 选出类别和最大分数，传回 [1,6,N]，候选数不变。逆变换先减 padding 再除缩放比例。

最新性能、DLA 支持与速度/精度取舍见 `reports/百帧优化与DLA验证报告_20261015.pdf`。矩形模型的形状变化、轻量 GMC 和固定机位关闭 GMC 属于显式策略选项；640 标准与 1280 默认精度方案继续保留。

整体部署与各方案的完整对比见 `reports/技术报告/Jetson视频工作台_部署与提速技术报告.pdf`。本机历史训练工程现在位于上一级 `开发归档/早期部署工程/`，开发导出时将 `tools/export_shape.py --project-root` 指向该目录。正式运行与可转发 ZIP 不依赖该开发工程。

512密集人群最新更新见 `reports/512密集人群优化/512密集人群精度优化报告.pdf`：极速方案NMS为0.55，分区增强方案每源帧5次推理，GMC仍关闭；跟踪/AP门槛分开。`tools/make_small_input_report.py`保留报告、实际结果截图和完整视频校验生成过程。826等宽度的编码行对齐修复位于 `VideoEncoder`，使用BGR补齐与BGRx裁回，不改变原图尺寸。
